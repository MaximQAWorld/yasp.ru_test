# Тестовое задание — Restful Booker API
Сервис: https://restful-booker.herokuapp.com (документация: /apidoc/index.html)

## Состав репозитория

- **`testcases.xlsx`** — позитивные и негативные тест-кейсы для эндпоинтов:
  `/auth`, `/booking` (POST), `/booking` (GET с фильтрами), `/booking/:id` (GET/PUT/PATCH/DELETE), `/ping`.
  Лист `Summary` — сводная статистика по количеству кейсов на каждый эндпоинт.
- **`Restful-Booker.postman_collection.json`** — Postman-коллекция (Collection v2.1), тест-кейсы перенесены
  в виде запросов с проверками во вкладке `Tests` (скрипты `pm.test`). Коллекция построена так, чтобы
  её можно было прогнать целиком: `/auth` сохраняет токен в переменную коллекции `token`,
  `POST /booking` сохраняет `bookingId`, используемый в последующих запросах.
- **`bug_report.xlsx`** — баг-репорт по дефектам, обнаруженным в ходе анализа API и тестирования.
  Каждый подтверждённый баг сопровождается **скриншотом реального ответа сервера** (столбец
  «Скриншот (реальный прогон)») — коды ответов проверены вживую через Postman, а не только по документации.

Оба `.xlsx`-файла открываются любым табличным редактором (Excel, LibreOffice Calc, Google Sheets).

## Известные дефекты (подтверждены реальным прогоном 25.09.2026, подробности и скриншоты — в bug_report.xlsx)

1. **BUG-01** (подтверждён): `DELETE /booking/:id` с валидной авторизацией возвращает **201 Created** вместо ожидаемых 200 OK / 204 No Content.
2. **BUG-02** (подтверждён): `GET /ping` возвращает **201** вместо 200 — нетипичный код для health-check эндпоинта.
3. **BUG-03** (подтверждён): `GET /booking?checkin=...&checkout=...` в одном из прогонов вернул **500 Internal Server Error** вместо корректной (или хотя бы стабильной) фильтрации по датам. Сама логика фильтрации при этом требует отдельной проверки: не подтверждено, действительно ли она игнорирует диапазон дат, когда не падает с 500.
4. **BUG-04a** (подтверждён): отсутствует валидация типа/диапазона в `POST /booking` — `totalprice`, переданный строкой, и отрицательное значение `totalprice` принимаются сервисом с кодом 200 без ошибок.
5. **BUG-04b** (подтверждён, серьёзность **High**): отсутствие обязательного поля `firstname` в `POST /booking` приводит к **500 Internal Server Error**, а не к ожидаемым 400 Bad Request — похоже на необработанное исключение на сервере.
6. **BUG-05** (подтверждён): `POST /auth` с неверными учётными данными возвращает **200** с телом `{"reason":"Bad credentials"}` вместо 401 Unauthorized.

## Важные технические заметки по тестированию

**Проблема с заголовком Cookie.** Заголовок `Cookie`, выставленный вручную в Postman (веб/Electron-версия),
**не отправляется** — браузерные клиенты блокируют ручную установку этого заголовка (forbidden header name).
Из-за этого способ авторизации через `Cookie: token=...`, описанный в документации restful-booker, не
срабатывает в веб-Postman и возвращает 403 даже с валидным токеном.
**Решение:** используется альтернативный способ авторизации restful-booker — `Authorization: Basic
base64(admin:password123)`. В коллекции запросы PUT/PATCH/DELETE с валидной авторизацией используют именно
Basic Auth; это подтверждено рабочим прогоном (BUG-01 воспроизведён именно так).

**Сброс данных.** Сервис сбрасывает данные каждые ~10 минут. Тестовые сценарии с зависимостью от ранее
созданного `bookingId` нужно выполнять быстро, одним циклом: `auth → create booking → use bookingId`,
не растягивая шаги во времени.

## Как запустить коллекцию

```bash
npm install -g newman
newman run Restful-Booker.postman_collection.json
```
