# Тестовое задание — Restful Booker API

Сервис: https://restful-booker.herokuapp.com (документация: /apidoc/index.html)

Состав репозитория
testcases.xlsx — позитивные и негативные тест-кейсы для эндпоинтов: /auth, /booking (POST), /booking (GET с фильтрами), /booking/:id (GET/PUT/PATCH/DELETE), /ping. Лист Summary — сводная статистика по количеству кейсов на каждый эндпоинт.
Restful-Booker.postman_collection.json — коллекция Postman (Collection v2.1), тест-кейсы перенесены в виде запросов с проверками на вкладку Tests (скрипты pm.test). Коллекция построена таким образом, чтобы ее можно было прогнать целиком: /auth сохраняет токен в переменной коллекции token, POST /booking сохраняет bookingId, используемый в последующих запросах.
bug_report.xlsx — баг-репорт по дефектам, обнаруженным в ходе анализа API и тестирования. Каждый подтвержденный баг сопровождается скриншотом реального ответа сервера (столбец «Скриншот (реальный прогон)») — коды ответов проверены в реальном времени через Postman, а не только по документации.

Оба xlsx-файла открываются любым табличным редактором (Excel, LibreOffice Calc, Google Sheets).

Известные дефекты (подтверждены реальным прогоном 25.09.2026, подробности и скриншоты — в bug_report.xlsx)
BUG-01 (подтверждено): DELETE /booking/:id с действительной авторизацией возвращает 201 Created вместо ожидаемых 200 OK / 204 No Content.
BUG-02 (подтверждено): GET /ping возвращает 201 вместо 200 — нетипичный код для эндпоинта проверки работоспособности.
BUG-03 (подтверждено): GET /booking?checkin=...&checkout=... В одном из прогонов вместо корректной (или хотя бы стабильной) фильтрации по датам возвращалась ошибка 500 «Внутренняя ошибка сервера». Сама логика фильтрации при этом требует отдельной проверки: не подтверждено, действительно ли она игнорирует диапазон дат, когда не падает с 500.
BUG-04a (подтверждён): отсутствует валидация типа/диапазона в POST /booking — totalprice, переданный строкой, и отрицательное значение totalprice принимаются сервисом с кодом 200 без ошибок.
BUG-04b (подтверждён, серьёзность High): отсутствие обязательного поля firstname в POST /booking приводит к 500 Internal Server Error, а не к ожидаемым 400 Bad Request — похоже на необработанное исключение на сервере.
BUG-05 (подтверждён): POST /auth с неверными учётными данными возвращает 200 с телом {"reason":"Bad credentials"} вместо 401 Unauthorized.
Важные технические замечания по тестированию

Проблема с заголовком Cookie. Заголовок Cookie, выставленный вручную в Postman (веб-версия/версия для Electron), не отправляется — браузерные клиенты блокируют установку этого заголовка вручную (forbidden header name). Из-за этого способ авторизации через Cookie: token=..., описанный в документации restful-booker, не работает в веб-версии Postman и возвращает ошибку 403 даже при наличии действительного токена. Решение: используется альтернативный способ авторизации restful-booker — Authorization: Basic base64(admin:password123). В коллекции запросы PUT/PATCH/DELETE с валидной авторизацией используют именно Basic Auth; это подтверждено рабочим прогоном (ошибка BUG-01 воспроизведена именно так).

Сброс данных. Сервис сбрасывает данные каждые ~10 минут. Тестовые сценарии с зависимостью от ранее созданного bookingId нужно выполнять быстро, одним циклом: авторизация → создание бронирования → использование bookingId, не растягивая шаги во времени.

Как запустить коллекцию

npm install -g newman
newman run Restful-Booker.postman_collection.json

Либо импортировать Restful-Booker.postman_collection. json в Postman (рекомендуется использовать десктопную версию — в ней нет ограничения на заголовок Cookie, актуального для веб-версии) и запустить через Collection Runner.
