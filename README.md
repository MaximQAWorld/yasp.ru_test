# Тестовое задание — Restful Booker API

Сервис: https://restful-booker.herokuapp.com (документация: /apidoc/index.html)

## Состав репозитория

- `testcases.xlsx` — позитивные и негативные тест-кейсы для эндпоинтов:
  `/auth`, `/booking` (POST), `/booking` (GET с фильтрами), `/booking/:id` (GET/PUT/PATCH/DELETE), `/ping`.
  Лист `Summary` — сводная статистика по количеству кейсов на эндпоинт.
- `Restful-Booker.postman_collection.json` — Postman-коллекция (Collection v2.1), тест-кейсы перенесены
  в виде запросов с проверками во вкладке `Tests` (скрипты `pm.test`). Коллекция построена так, чтобы
  её можно было прогнать целиком: `/auth` сохраняет токен в переменную коллекции `token`,
  `POST /booking` сохраняет `bookingId`, используемый в последующих запросах.
- `bug_report.xlsx` — баг-репорт по дефектам, обнаруженным в ходе анализа API и тестирования.

## Известные дефекты (подтверждены реальным прогоном 25.09.2026, подробности в bug_report.xlsx)

1. **BUG-01** (подтверждён): `DELETE /booking/:id` возвращает 201 Created вместо 200/204.
2. **BUG-02** (подтверждён): `GET /ping` возвращает 201 вместо 200.
3. **BUG-03** (требует доп. проверки): `GET /booking?checkin=...&checkout=...` в одном из прогонов вернул 500 Internal Server Error вместо ожидаемой (пусть и некорректной) фильтрации.
4. **BUG-04a** (подтверждён): отсутствует валидация типа/диапазона в `POST /booking` — `totalprice` как строка и отрицательное значение принимаются с кодом 200.
5. **BUG-04b** (подтверждён, серьёзность High): отсутствие обязательного поля `firstname` в `POST /booking` приводит к **500 Internal Server Error**, а не к 400 Bad Request — необработанное исключение на сервере.
6. **BUG-05** (подтверждён): `POST /auth` с неверными учётными данными возвращает 200 вместо 401.

### Важная техническая заметка по тестированию

Заголовок `Cookie`, выставленный вручную в Postman (веб/Electron-версия), **не отправляется** — браузерные клиенты блокируют ручную установку этого заголовка (forbidden header name). Из-за этого способ авторизации через `Cookie: token=...`, описанный в документации restful-booker, не работает в веб-Postman и возвращает 403 даже с валидным токеном.
**Решение:** использовать альтернативный способ авторизации — `Authorization: Basic base64(admin:password123)`. В коллекции запросы PUT/PATCH/DELETE с валидной авторизацией используют именно Basic Auth.

Также сервис сбрасывает данные каждые ~10 минут — тестовые сценарии с зависимостью от ранее созданного `bookingId` нужно выполнять быстро, одним циклом (auth → create → use).

## Как запустить коллекцию

```bash
npm install -g newman
newman run Restful-Booker.postman_collection.json
```
